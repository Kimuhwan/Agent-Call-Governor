## Real Codex A/B trial

The same four read-only tasks were executed once without the governor and once with the `balanced` governor policy at commit `c8ec476`. The tasks covered supplied-text rewriting, repository edge-case inspection, current official GitHub Actions verification, and high-risk under-call analysis.

| Metric | Normal execution | Governor | Change |
| --- | ---: | ---: | ---: |
| Tasks completed | 4 / 4 | 4 / 4 | No loss |
| Direct-tool calls | 7 | 3 | -57% |
| Subagent calls | 2 | 0 | -100% |
| Total calls | 9 | 3 | -67% |
| Identical retries | 0 | 0 | No change |
| Blind quality average | 8.63 / 10 | 8.88 / 10 | +0.25 |

A third agent judged only the anonymized answers and selected the Governor result as the stronger overall response. Both conditions found the same budget-accounting defect. The normal condition added a retry-ordering finding; the Governor condition added a stronger high-risk classification and independent-verification recommendation.

This is a single matched trial, not a statistically significant production benchmark.

## Improvements implemented from A/B findings

- Derive `budget.used` from matching history entries when it is omitted.
- Reject an explicit `budget.used` lower than the matching history count.
- Track `agent` and `direct-tool` history ledgers separately through `history.budget_kind`.
- Guarantee at least one materially changed-strategy retry for high-risk work, even under `strict`.
- Add four unit tests and two deterministic policy cases for these behaviors.

## Finding resolved during iteration

The initial forward evaluation found an ambiguity between mandatory user-requested actions and duplicate prevention. The policy now states explicit precedence: block an identical fingerprint first, then apply mandatory exceptions. The post-change evaluation correctly rejected an unchanged repeated lookup while allowing a new explicitly requested publication action.

## Limitations

These results validate checked-in rules and scenario-level routing judgment. The A/B result is directional evidence only; it does not establish a production call-reduction percentage or end-to-end task success rate. Real workload telemetry is still needed to measure cost, latency, task success, and under-call failures over time.
